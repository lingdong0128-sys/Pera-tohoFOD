# 视口盒子模型（显示层重构规格）

> 2026-09-14 设计定稿并**已实现**（同日）。替代 dynamic_loader 的 current_display/scroll_offset 视口实现，
> 实现：`DynamicLoader._compose_box` 及配套（见文件内 [盒子模型] 注释）。实测通过：
> 启动渲染、MCP 全链路、真鼠标滚轮回看（画面差分验证）、真鼠标点击 [0]start（命中矩形→INPUT 链路）。
> 顺带修复：INPUT 循环每帧新建 Clock 导致限帧从未生效（CPU 空转一个核的旧 bug）。
> 未逐项目测（留档）：回看时"↓ 有新内容"提示的视觉表现、PgUp/PgDn 整盒翻页、bad_apple 播放器适配。

## 一、核心概念

**行是流，页是盒子。**

```
行（流） ═════════════════════════════════▶
              ┌────────────┐
              │    盒子     │  ← 唯一被排版、被渲染的实体
              │ （容量=一屏） │
              └────────────┘
```

- **流**：所有 PRINT/PRINTIMG 产生的行，按序排列，住在内存（现有的 `history` 数组，带 seq 序号）。流是数据的唯一真相源。
- **盒子**：容量为一屏的观察窗，是唯一被维护的实体。没有第 N 页、没有页码、没有页边界数据——"翻页"只是盒子沿流前进一格的观感。
- **滚动 = 让流行进/倒流着穿过盒子**，不是在多个页面之间移动。

## 二、状态（一共只有三个量）

| 状态 | 类型 | 说明 |
|---|---|---|
| 流 | `List[ConsoleContent]` | 现有 history；seq 单调序号不变（MCP 游标依赖它） |
| 盒子位置 | 一个标量（锚定行号/偏移） | 唯一的滚动状态 |
| 盒子容量 | 像素 | 内容区高度；虚拟画布下（1600×1000 设计坐标系）为常数，窗口拉伸不改变它 |

## 三、行为规则

### 追加（PRINT/PRINTIMG）
1. 行进入流尾；
2. 盒子在流尾（追更状态）→ 盒子随行推进，旧行从顶端流出（流水线）；
3. 盒子不在流尾（玩家回看中）→ 新行攒在流里，盒底显示"↓ 有新内容"提示，不打断阅读。

### 滚动
- 滚轮：盒子沿流连续移动，一格 3 行（现状习惯）；
- PgUp/PgDn：移动一个盒子的量；
- 滚到流尾即回到追更状态。

### 容量（按像素，不按行数）
- 文本行按行高扣减，图片项按图高扣减，同一把像素尺子；
- **文本可切**：一段文字最后几行装不下 → 切到盒子后续位置；
- **图片不可切**：装不下 → 整体留在流里，等盒子前进到装得下的位置再进来，本屏留白；
- 边界：单项高度超过整盒的图片需要钳制/缩放（极端情况，允许后补）。

### 渲染
- 盒子内容**只在三种时机重排**：流追加且在流尾 / 盒子移动 / 容量变化；
- 帧循环只 blit 盒子的缓存布局——每帧全量重算（问题清单 🟠6）在此模型下无处发生。

## 四、与现有系统的关系

- **替换**：`current_display`、`_update_current_display()`、`scroll_up/down/to_top/...`、`scroll_offset <= 5` 自动滚动启发式（改为"在流尾"布尔量）；
- **不动**：`history` 数组与 seq（MCP `pera_read_output` 依赖）、`_write_to_log` 日志、INPUT 输入区（固定在盒子之外，不参与分页）、点击区域注册（跟随盒子重排一起更新）；
- **决策记录**：流住内存（2026-09-14 定）；日志文件继续作为磁盘侧副本，但盒子回滚不读它。
