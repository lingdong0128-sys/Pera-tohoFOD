# MID 渲染管线（MusicBox 音源方案）

> 2026-09-14 建立，2026-09-17 升级为双方案。解决 pygame 播 `.mid` 走 Windows GS Wavetable
> Synth（祖传 2MB 音色库，"效果是一大坨"）的问题。

## 方案一：SF2 直通（2026-09-17 起，现行首选）

自制了一个**带 FluidSynth 后端的 SDL2_mixer.dll** 替换 pygame 自带的那个（构建方法与全部
材料见 [SoundFont_c_dll/](../SoundFont_c_dll/README.md)），MIDI 在 SDL 内部直接用 SF2
软件合成，`pygame.mixer.music.load('xxx.mid')` 原样可用，不再经过 GS Wavetable，也不需要
预渲染缓存。

- **DLL 层接口**：SDL_mixer 原生 `Mix_SetSoundFonts(sf2路径)`（2.0 起就有的公开 API）；
- **pygame 层新接口（已内建于特化 wheel，+sf2.2 起）**：
  `pygame.mixer.music.load(filename, sf2url=None)`——`.mid + sf2url` 设音色库并直通；
  `.mid` 不带 sf2url 显式清空音色库走 Windows 原生 MIDI；其余格式行为同官方。
  转接代码由 `wheel打包/repack_wheel.py` 注入 wheel 内 `pygame/__init__.py` 末尾
  （含关键一环：首次用 sf2url 时**全路径预加载** libfluidsynth-3.dll——SDL 的
  `SDL_LoadObject` 按裸文件名 LoadLibrary 找不到 pygame 目录里的运行时，会静默回退
  GS Wavetable，这个坑踩过，见 README）。探测标记：`pygame.mixer.music._sf2_load`；
- **Musicbox 接入**：`MusicBox.__init__` 探测特化标记 + `tools/soundfonts/` 第一个
  sf2/sf3，二者齐备则 `sf2_direct=True`，mid 加载时直接
  `pygame.mixer.music.load(url, sf2url=音色库)`；`_resolve_music_file` 在直通可用时
  返回 mid 本身，**不可用时自动落回方案二**（找同名 ogg 缓存）——两套方案无缝互为兜底；
- **部署形态**：`.venv/Lib/site-packages/pygame/` 下换 SDL2_mixer.dll + 一套 FluidSynth
  运行时 dll（libfluidsynth/glib/sndfile 等）。原版备份在
  `SoundFont_c_dll/备份-pygame原版/`，还原 = 拷回 + 删 fluid 系 dll。
- **分发给别人**：特化版 wheel（当前 `pygame-2.6.1+sf2.2-cp313-cp313-win_amd64.whl`）
  发布在本仓库 GitHub Release（tag `pygame-sf2-2`，公开匿名直链）——requirements.txt
  指向该直链（win64+py3.13 自动装特化版，其他环境回退官方 pygame 并走 ogg 管线），
  全新 venv 从直链安装+新接口测试已端到端 PASS。音色库仍是 `tools/soundfonts/`
  （不入 git，自行获取，见该目录 README）。重打包方法与其他分发路线见
  SoundFont_c_dll/README.md。
- **代价**：播放期间 SF2 常驻内存（SGM-V2.01 约 250MB）；每次 load mid 有约 0.3s 的
  音色库加载。打包 exe 分发时推荐仍走方案二产物（ogg），玩家机器零依赖。

方案一已实测验证（模块表证据 + 全格式回归）：
`SoundFont_c_dll/test_sf2_bridge.py`。

## 方案二：预渲染管线（2026-09-14，兜底）

pygame.mixer 播 `.mid` 时 SDL_mixer 把合成甩给系统 MIDI 设备（Windows 上就是 GS Wavetable）。
本管线**绕开运行时合成**：开发期用 FluidSynth + SoundFont 把 mid 预渲染成 ogg 缓存，
游戏运行时 `MusicBox.load_music` 自动优先加载同名 `.ogg/.wav`——玩家零依赖、打包 exe 无顾虑、
还顺便解决了 Windows 独占的跨平台问题。方案一不可用（如 venv 重建、dll 没部署）时自动启用。

```
Musicbox/xxx.mid ──(tools/mid渲染.py: FluidSynth + SF2 → wav → ffmpeg → ogg，一次性)──▶ Musicbox/xxx.ogg
                                                                              │
游戏运行时 MusicBox.load_music("xxx.mid") ──自动解析──▶ 播放 xxx.ogg（pygame.mixer）
```

## 使用

```shell
.venv/Scripts/python tools/mid渲染.py          # 只渲染没有缓存的 mid
.venv/Scripts/python tools/mid渲染.py --force  # 全部重渲（换音色库后用这个）
.venv/Scripts/python tools/mid渲染.py --sf2 路径.sf2
```

往 `Musicbox/` 扔新 mid 后跑一次即可；`musicbox.csv` 里的路径**不用改**（仍写 .mid，
加载时自动解析）。

## 组件（均不入 git，见 .gitignore）

| 组件 | 位置 | 获取 |
|---|---|---|
| FluidSynth 2.6.0 | `tools/fluidsynth/` | [官方 Release](https://github.com/FluidSynth/fluidsynth/releases) win10-x64 包 |
| 音色库 SF2/SF3 | `tools/soundfonts/` | 推荐 [SGM-V2.01](https://archive.org/download/SGM-V2.01)（免费）；详见该目录 README |
| ffmpeg（ogg 压缩） | `.venv` 内置 | moviepy 附带的 imageio-ffmpeg，无需安装 |

## 音源选择（东方相关）

ZUN 的 MIDI 时代（红魔乡～花映冢）使用 **Roland Sound Canvas 系（SC-88Pro 为代表）**——
所谓"东方原版 MIDI 音色"指的就是它。SC-88Pro 的 SF2 转制版社区有流通（硬件 ROM 提取，
法律灰色，自行获取）；合法免费的最佳替身是 SGM-V2.01（雅马哈系风格，东方编曲社区常用）。

## 已知边界

- mid 的循环信息不会带入 ogg——循环靠 `play(loops=-1)`（music_control 已是这么做的）；
- 渲染增益固定 `-g 0.5`，整体过响/过轻可改 `tools/mid渲染.py`；
- 系统级替代方案（本机爽、不改代码）：装 VirtualMIDISynth + 音色库设为默认 MIDI 设备，
  适合自己玩，不适合随游戏分发。
